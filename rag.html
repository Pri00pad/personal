1. Knowledge Base

Start with documents containing information the LLM may need.
Important: the knowledge base is the source information itself. The vector database stores embeddings together with the original chunk text and metadata.

2. Chunking

Documents are divided into smaller pieces so retrieval can find the most relevant information.

3. Embeddings + Vector Database

Every chunk is converted into a numerical vector. Similar meanings should produce vectors that are closer together.
Demo dimension: 24
Embedding

A numeric representation of text that attempts to capture semantic meaning.

Dimensions

Embedding dimensions are model-dependent. They may be 384, 768, 1024, 1536, 3072 or another size.

Vector Database

Stores embeddings plus original chunk text, document IDs, page numbers, permissions and other metadata.

Similarity

Cosine similarity is common. Dot product and Euclidean distance may also be used.

4. Retrieval

The user query is also converted into an embedding and compared with stored chunk embeddings.

5. Re-ranking

A second relevance check can reorder the candidate chunks.
Production systems may use dedicated reranker models, cross-encoders, LLMs, metadata, permissions, freshness, or business rules.

6. Augmented Prompt

Retrieved chunks are inserted into the prompt together with the original user question.

7. Generation

The LLM receives the augmented prompt and generates its answer.

Run retrieval and generate an answer.

Why Hybrid Search Matters

Semantic search and keyword search solve different problems.
Vector Search

Excellent for meaning. A query like "How long can I send an electronic item back?" may match text saying "electronics are returnable within 30 days."

Keyword Search

Excellent for exact identifiers such as PCXM3ON, invoice numbers, error codes, contract IDs or account numbers.

Hybrid Search

Combines semantic similarity with exact lexical matching. This is especially useful when a query includes both concepts and identifiers.

Re-ranking

Retrieve several candidates quickly first, then apply a more expensive relevance check to select the strongest context.
